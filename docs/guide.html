Guide d'utilisation — BucketPush

Dernière mise à jour : 11 novembre 2026 · English version below

BucketPush est un navigateur et un client de transfert pour serveurs de stockage compatibles S3 (Backblaze B2, Scaleway, Cloudflare R2, MinIO, AWS S3, etc.), conçu pour envoyer et recevoir des fichiers très volumineux (plusieurs dizaines voire centaines de Go) sans jamais saturer la mémoire ni planter.

1. Obtenir des identifiants S3

BucketPush ne fournit pas de stockage : vous connectez votre propre compte chez un fournisseur compatible S3. Dans l'app, l'écran « À propos → Fournisseurs S3 » liste plusieurs options avec offre d'essai gratuite. Chez n'importe quel fournisseur, il vous faudra créer :

  • un bucket (l'espace de stockage) ;
  • une clé d'accès (access key ID + secret access key), avec les droits lecture/écriture sur ce bucket.

Notez aussi l'endpoint (l'adresse du serveur, ex. https://s3.eu-central-003.backblazeb2.com) — votre fournisseur l'affiche dans sa documentation ou son tableau de bord.

2. Créer un profil de connexion

  1. Onglet Profils → Nouveau profil.
  2. Renseignez un nom, l'endpoint, le bucket, et collez vos deux clés.
  3. Path-style : à activer pour la plupart des fournisseurs S3-compatibles (Backblaze B2, MinIO…) ; à désactiver pour AWS S3 classique.
  4. Tester la connexion avant d'enregistrer.

Vous pouvez créer plusieurs profils (plusieurs fournisseurs, ou perso/pro) et basculer de l'un à l'autre depuis l'onglet Profils ; le navigateur se recharge automatiquement à la racine du bucket sélectionné.

3. Parcourir le bucket

L'écran principal liste dossiers et fichiers du bucket connecté. Appuyez sur un dossier pour y entrer, utilisez le fil d'Ariane en haut pour remonter. Le champ de filtre permet de chercher dans le dossier courant.

4. Envoyer et recevoir des fichiers

Le bouton + ouvre le sélecteur de fichiers du système — choisissez-en un ou plusieurs, même très volumineux. L'envoi démarre immédiatement et continue en arrière-plan : vous pouvez éteindre l'écran ou changer d'application, le transfert se poursuit (notification de progression). Une coupure réseau met le transfert en pause ; il reprend automatiquement dès que la connexion revient, sans tout recommencer.

Pour télécharger, sélectionnez un ou plusieurs fichiers puis Télécharger ; pour déplacer, Déplacer puis choisissez le dossier de destination.

5. La file d'attente

L'onglet File d'attente reste consultable même sans transfert en cours. Il affiche le débit cumulé en haut, et trie les éléments par état (terminés, en cours, en attente, échecs, annulés). Un appui long sur un élément propose pause, annulation ou nouvelle tentative. Annuler tout arrête tout en une fois.

6. Versions et fichiers « fantômes »

Si le versioning est activé côté bucket, supprimer un fichier ne l'efface pas vraiment : un « marqueur de suppression » le cache, l'ancienne version reste stockée (et facturée) tant qu'elle n'est pas purgée. L'écran Versions d'un fichier permet de restaurer (retirer le marqueur) ou de purger définitivement les anciennes versions.

7. Outils

OutilUtilité
Taille de ce dossier / du dépôtCalcule l'espace occupé, y compris les anciennes versions non visibles dans l'explorateur.
Purger les anciennes versionsVide l'historique de versions d'un dossier ou de tout le bucket — libère l'espace facturé par le fournisseur.
Nettoyer les uploads inachevésUn transfert interrompu laisse des « parts » orphelines côté serveur (facturées, invisibles). Cet outil les retrouve et les annule. Mode Prudent = ignore les transferts récents/actifs ; Tout annuler = force tout.

8. Paramètres : globaux et par profil

L'écran Paramètres (icône ⚙) définit des valeurs par défaut communes à tous les profils : taille de part, nombre de parts/fichiers en parallèle, langue, etc. Dans l'écran d'édition d'un profil, chaque réglage peut être laissé « Hérité » (suit la valeur globale) ou basculé en « Spécifique » pour le figer juste pour ce profil.

  • Taille de part : vide = adaptatif (32 Mio, agrandi automatiquement pour les fichiers énormes afin de rester sous la limite de 10 000 parts par fichier).
  • Parts / fichiers en parallèle : plus de parallélisme va plus vite jusqu'à saturer votre connexion ou déclencher des ralentissements (503 SlowDown) côté fournisseur — baissez si ça arrive.
  • Ne pas ré-uploader si déjà présent : une requête HEAD avant chaque envoi évite de retransmettre un fichier déjà sur le serveur.

9. Dépannage

« Connexion échouée » au test : vérifiez que l'endpoint commence par https://, qu'il ne contient pas le nom du bucket, que le bucket existe bien chez le fournisseur, et que la clé a les droits lecture/écriture sur ce bucket précis. Essayez de basculer Path-style.

Transfert très lent : la limite est presque toujours la connexion (Wi-Fi, 4G/5G) ou le débit autorisé par votre forfait fournisseur, pas l'application — elle ne fait que streamer les données sans jamais les charger entièrement en mémoire.

Le transfert s'arrête quand l'app est fermée : vérifiez que l'optimisation de batterie n'est pas appliquée à BucketPush dans les réglages Android de votre téléphone.

User Guide — BucketPush

Last updated: 11 November 2026

BucketPush is a browser and transfer client for S3-compatible storage servers (Backblaze B2, Scaleway, Cloudflare R2, MinIO, AWS S3, etc.), built to send and receive very large files (tens or hundreds of GB) without ever choking memory or crashing.

1. Getting S3 credentials

BucketPush doesn't provide storage itself: you connect your own account with an S3-compatible provider. In the app, the "About → S3 providers" screen lists several options with a free trial tier. With any provider you'll need to create:

  • a bucket (the storage space);
  • an access key (access key ID + secret access key), with read/write rights on that bucket.

Also note the endpoint (the server address, e.g. https://s3.eu-central-003.backblazeb2.com) — your provider shows it in its docs or dashboard.

2. Creating a connection profile

  1. Profiles tab → New profile.
  2. Enter a name, the endpoint, the bucket, and paste both keys.
  3. Path-style: turn on for most S3-compatible providers (Backblaze B2, MinIO…); off for plain AWS S3.
  4. Test connection before saving.

You can create several profiles (different providers, or personal/work) and switch between them from the Profiles tab; the browser automatically reloads at the root of the selected bucket.

3. Browsing the bucket

The main screen lists folders and files in the connected bucket. Tap a folder to enter it, use the breadcrumb at the top to go back up. The filter field searches within the current folder.

4. Uploading and downloading files

The + button opens the system file picker — pick one or several files, even very large ones. The upload starts immediately and keeps running in the background: you can turn off the screen or switch apps, the transfer continues (with a progress notification). A network drop pauses the transfer; it resumes automatically once the connection is back, without starting over.

To download, select one or more files then Download; to move them, Move then pick the destination folder.

5. The queue

The Queue tab stays available even with nothing running. It shows the combined speed at the top, and sorts items by state (done, running, pending, failed, canceled). Long-press an item for pause, cancel or retry. Cancel all stops everything at once.

6. Versions and "ghost" files

If versioning is enabled on the bucket, deleting a file doesn't really erase it: a "delete marker" hides it, and the old version stays stored (and billed) until purged. A file's Versions screen lets you restore it (remove the marker) or purge old versions for good.

7. Tools

ToolWhat it's for
Size of this folder / repoComputes the space used, including old versions not shown in the browser.
Purge old versionsClears the version history of a folder or the whole bucket — frees space billed by the provider.
Clean unfinished uploadsAn interrupted transfer leaves orphan "parts" on the server (billed, invisible). This tool finds and cancels them. Safe mode skips recent/active transfers; Abort all forces everything.

8. Settings: global and per-profile

The Settings screen (⚙ icon) sets defaults shared by every profile: part size, parallel parts/files, language, etc. On a profile's edit screen, each setting can stay "Inherited" (follows the global value) or be switched to "Specific" to pin it just for that profile.

  • Part size: empty = adaptive (32 MiB, grown automatically for huge files to stay under the 10,000-parts-per-file limit).
  • Parallel parts / files: more parallelism goes faster until it saturates your connection or triggers provider throttling (503 SlowDown) — lower it if that happens.
  • Skip if already uploaded: a HEAD request before each upload avoids resending a file already on the server.

9. Troubleshooting

"Connection failed" on test: check that the endpoint starts with https://, doesn't include the bucket name, that the bucket actually exists with the provider, and that the key has read/write rights on that exact bucket. Try toggling Path-style.

Transfer is very slow: the limit is almost always your connection (Wi-Fi, 4G/5G) or your provider's plan throughput, not the app — it only streams data and never loads it fully into memory.

Transfer stops when the app is closed: check that battery optimization isn't applied to BucketPush in your phone's Android settings.
